# 等保测评实务手册（主攻方向：这个岗位每天在干嘛）

## 1. 一个测评项目全流程（背）

**签合同 → 资料收集 → 现场测评（访谈/检查/测试）→ 出具报告 → 整改 → 复测 → 备案**

你作为初级测评师，大部分时间在第 2–4 步。

## 2. 现场测评三件事（核心）

### 访谈（问管理员）
- 有哪些资产、边界在哪、网络怎么分的
- 制度文档：安全管理制度、应急预案、备份策略有没有
- 口令策略、日志留存多久（等保要求至少 6 个月）
- 最近出过什么事、怎么处置的

### 检查（配置核查）
- 操作系统/数据库/网络设备的安全基线：口令复杂度、是否开审计、补丁情况、多余账号
- 边界设备：防火墙策略、访问控制
- 机房：门禁、UPS、防水火

### 测试（工具验证）
- 漏洞扫描（拿到授权后在测评范围内扫）
- 配置验证（比如：真的建个弱口令账号试试能不能登录）
- 功能测试：备份能不能恢复、审计日志能不能查

## 3. 初级测评师的分工（入职前半年）

填测评记录表 → 配置核查 → 跑扫描工具 → 写报告里的"问题描述"部分 → 跟着出差。

**这行的现实**：出差多（现场才能测），报告多（交付物就是报告），所以"会写、写清楚"比"技术多深"更重要——你的 [渗透测试报告写作模板.md](20_渗透测试报告写作模板.md) 就是为这个准备的。

## 4. 常用工具（面试报名字）

- 漏洞扫描：绿盟 RSAS、Nessus 类
- 配置核查：基线核查脚本/工具
- Web：Burp、Nmap、sqlmap（你都有）
- 文档：Word/Excel 要熟，报告靠它们

## 5. 报告长什么样

简介 → 总体评价 → **问题列表**（每个问题：对应测评项 / 现象描述 / 风险分析 / 整改建议）→ 得分与结论。

每个"问题"的写法，和你 DVWA 迷你报告里的漏洞条目是同一个逻辑——你已经在练了。

## 6. 面试高频 6 题（结合 [等保测评要点速记.md](28_等保测评要点速记.md)）

1. 测评流程？→ 七步背出来
2. 现场做什么？→ 访谈、检查、测试三件套
3. 测评结论怎么定？→ 符合/部分符合/不符合/不适用 + 综合得分
4. 会用什么工具？→ 报你实际用过的（别报没碰过的）
5. 能接受出差吗？→ 如实，说清范围
6. 让你写一段"整改建议"看看 → 这就是为什么第 2 周要交迷你报告

## 7. 现在就能练的项目（写进简历）

**拿你自己的 Kali + Windows，按等保基线自查一遍，写一份 5 个问题的《自测与整改报告》。**

做法：找一份公开的等保基线检查表 → 逐项查自己 → 记下"不符合项" → 每条写整改建议。做完放 GitHub，简历写"完成一次等保基线自测，输出整改报告"——应届生简历上出现"等保"两个字，HR 会多看一眼。
