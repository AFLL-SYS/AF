# 渗透测试报告写作模板（乙方安服的交付物就是报告）

> 一句话：技术再牛，报告稀烂，等于白干。面试官让你"讲讲你的项目"，讲的就是报告结构。

## 1. 报告标准骨架（七大块）

1. **封面/项目信息**：委托方、测试范围（IP/域名清单）、测试时间、密级、双方人员
2. **摘要（最重要，给领导看的）**：整体风险结论 + 高危几个 + 一句话建议。领导只看这一页
3. **测试概述**：范围、方法（黑盒/白盒）、工具（Nmap/Burp/sqlmap）、授权依据
4. **漏洞详情**：每条漏洞一个标准条目（见下）
5. **风险统计表**：高危 x 个 / 中危 x 个 / 低危 x 个
6. **整改建议汇总**：按"先修什么"排序
7. **附录**：工具输出、扫描原始记录

## 2. 漏洞条目模板（照抄填空，每个漏洞一页）

```
【高危】SQL 注入
漏洞位置：http://192.168.1.10/dvwa/vulnerabilities/sqli/?id=1
漏洞描述：id 参数未做任何过滤，被直接拼接进 SQL 语句。
         攻击者可用 union 查询从 information_schema 拖出全部用户数据。
证明截图：（注入成功、拖出数据的截图，红框标出关键位置）
复现步骤：1. 访问 xx 页面  2. 输入 xx  3. 出现 xx 现象
风险等级：高危（CVSS 8.8）
修复建议：1. 使用参数化查询（预编译语句）
          2. 数据库账号最小权限
          3. 关闭报错回显，统一错误页
```

## 3. 等级怎么定（不背 CVSS 也能判断）

- **高危**：能拿权限、能拖敏感数据、能直接攻下系统
- **中危**：信息泄露、弱口令、缺少防护配置
- **低危**：版本信息泄露、不必要端口开放、小配置问题

拿不准就写"参考 CVSS 评分，综合业务影响定为 X 级"。

## 4. 写作三铁律

1. **每个漏洞必须有截图 + 复现步骤**——别人照着你的步骤能重现，报告才成立
2. **修复建议必须可执行**——写"参数化查询""改最小权限"，不写"加强安全意识"
3. **措辞客观**——写"攻击者可能获取数据"，不写"数据已经泄露"；不夸大、不甩锅

## 5. 常见低级错误（面试官扫一眼就 pass）

- 只贴扫描器原始输出，一行都不分析
- 截图没有标注，看不出问题在哪
- 建议写"加强安全管理"这种废话
- 不写影响面（"能拖全库数据"必须点明）
- 名词乱用（把"漏洞"叫"病毒"）

## 6. 练习任务（第 2 周结束前交）

把你 DVWA 四关的截图整理成一份 **4 个漏洞的迷你报告**（就按上面的模板，共 4 页 + 1 页摘要）。

这份东西放进 GitHub，简历里写"能独立撰写渗透测试报告"就有证据了——**应届生里没几个人拿得出这个。**
